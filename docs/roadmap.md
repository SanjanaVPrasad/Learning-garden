# Proposed roadmap: Learning Garden

Planning document, 25 November 2026. No item below is completed by this documentation commit; priorities can change after research.

| Priority | Work | Acceptance criteria |
| --- | --- | --- |
| P0 — Next | Reconcile repository and hosted-release source | Reviewed source diff; no personal records or hosting secrets; calendar code and relevant checks included; README matches runnable features |
| P0 — Next | Test the main workflow with five potential users | Anonymised task observations, assistance and failure points recorded; top repeated problem selected |
| P1 — Soon | Fix the top usability obstacle | Acceptance criteria linked to observations; affected workflow retested |
| P1 — Soon | Strengthen recovery and onboarding | Users understand browser-only storage and can export and recover a demonstration record |
| P2 — Later | Prepare a public demonstration | Synthetic data, clear setup or demo instructions and an accurate limitations statement |
| P3 — Explore | Evaluate an AI study-summary feature | Compare with the existing manual workflow; evaluate accuracy, edit effort, privacy, per-session cost and a defined budget cap before deciding to integrate |

## Case-study and contribution routine

For each meaningful change: open an issue with the user problem and acceptance criteria, make a focused change, record validation, and summarise the outcome in a pull request or release note. Describe the AI assistance and the human review accurately. Keep the problem, decision, result and remaining limitation together.

No adoption, ROI or model-quality results are asserted by this roadmap.
